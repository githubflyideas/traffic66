## 如何复跑

要求 Python 3.12+、Git、已有 Go 工具链。先取得包含上述基线提交的 traffic66 checkout，不需要修改生产代码。提供一个全新或空的工作目录：

```bash
python docs/review/reproduce.py \
  --go /absolute/path/to/go \
  --work /absolute/path/to/empty-review-workspace \
  --output /absolute/path/to/review-output.txt
```

Windows 可传入 `C:/.../go.exe`。可用 `--cache` 指定现有 Go build cache；脚本不会安装工具或重启 Docker。运行时固定 GOTOOLCHAIN=local，因此日志中的真实版本才是验证版本。

脚本依次归档精确基线、跑原包测试、复制 `.go.txt` 探针到隔离源目录、运行行为刻画和修复目标断言。最后一步在当前基线上预期退出1；**这个失败表示复现到缺陷，不是质量门禁通过**。基线检查失败返回2，其他环境或准备异常也可能产生非零退出；必须查看完整日志，不能将任意失败都当作成功复现。

NF 探针复用基线原测试中的 IPFIX 模板和 helper，因此应在完整测试包中运行，不是单独一个 go 文件。行为模式通过记录当前表现；设置 REVIEW_EXPECT_FIXED=1 后检查期望修复结果。
