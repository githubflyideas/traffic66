新規インストールした traffic66 には admin / traffic66 でサインインし、初回サインイン時にご自身のパスワードを設定します。Windows では traffic66.exe をダブルクリックするとブラウザーが開きます。先に動きを確認したい場合は、traffic66 demo が 1 日分の履歴と一連の攻撃を含む模擬社内ネットワークを作成します。

Windows について補足します。表のプロジェクトのほとんどは Linux または Docker 上でしか動きません。traffic66 は同じコードから Windows、Linux、macOS のネイティブプログラムをビルドしており、WSL も Docker も不要です。小規模な組織では、監視用の端末が Windows PC であることが少なくありません。

3 ステップ
ダウンロードから最初のグラフまで

日本のネットワーク運用との関係

多くの職場では、インターフェースの使用量は Zabbix などで SNMP により監視されています。そこにフロー分析を加えると、同じ回線についてフローと SNMP の二つの数値が並び、両者は一致しないことがよくあります。traffic66 のインターフェース照合は、この差を同じグラフ上に並べ、理由まで示すためのページです（次の章で説明します）。sFlow のカウンターが届く機器ではそのまま使い、NetFlow の機器では 設定 → 名前 に snmp 行を 1 行追加します。なお、現在の SNMP 読み取りは SNMPv2c で、コミュニティ名は平文で保存されるため、読み取り専用のコミュニティをお使いください。

国内でよく使われる機器のフロー出力は、各社の公式ドキュメントで次のとおり確認しました。Cisco IOS XE は Flexible NetFlow で NetFlow v9 または IPFIX を出力します。Juniper の Junos は sFlow に対応しています。Fortinet の FortiGate は NetFlow v9 と sFlow を出力できます。アライドテレシスの AlliedWare Plus は sFlow エージェントを備えています。NEC UNIVERGE IX はソフトウェア ver.8.9 以降で sFlow version 5 のエージェントに対応していますが、ver.9.5 以前は受信方向のみを収集し、トンネルインターフェース単位のフロー情報には対応していません。NEC は、100 Mbps 回線ではサンプリングレート 200 以上、1 Gbps 回線では 2,000 以上を目安として挙げています。同 FAQ にはカウンターサンプルの記載がないため、インターフェース照合で比較するカウンターが届かない場合は SNMP 行で補ってください。

閉域網での運用も想定しています。traffic66 はインターネット接続がなくても動作し、別途データベースを導入する必要もありません。国・AS の判定には DB-IP の無償 Lite データベースを同梱しており、脅威リストは 1 行に 1 アドレスを書いたローカルのテキストファイルです。Web UI は平文の HTTP なので、信頼できないネットワークでは -addr 127.0.0.1:8066 を指定し、TLS プロキシまたは SSH トンネルの背後に置いてください。ライセンス上、100 人未満の組織は無償で、それ以上の組織は 30 日後に登録が必要です（後述）。

2. フローの数値はインターフェースカウンターと一致するか

フローツールが必ず受ける質問です。グラフでは上位回線が 800 Mb/s、Zabbix の SNMP では 600 Mb/s。どちらが正しいのでしょうか。

フローの数値は推定値で、サンプリングしたパケットにサンプリングレートを掛けたものです。traffic66 にはこのための専用ページ、インターフェース照合があります。各インターフェースについて、フローからの推定値と機器自身のカウンター（sFlow カウンターまたは SNMP）を一つのグラフに描き、差とサンプリングによる統計誤差を計算します。差がサンプリングで説明できる範囲を超えると、考えられる原因を示します。サンプリングされていないインターフェース、同じトラフィックの 2 か所でのサンプリング、途中で失われたエクスポートパケット、まだ受信していないサンプリングレート、のいずれかです。

その裏では、目立たない処理をいくつか行っています。機器が実際に適用したサンプリングレートを使うこと。サンプリングレートが届くまでレコードを保留し、1:1 として数えないこと。失われたエクスポートパケットを補正すること。長いフローを継続した各分に振り分けること。そして、インターフェースカウンターにはイーサネットのオーバーヘッドが含まれるため、NetFlow のバイト数にもそれを加えることです。

ほかのプロジェクトの対応状況です。

traffic66フロー推定値と機器のカウンターを一つのグラフに表示し、差と統計誤差を計算して原因を示します。sFlow カウンターは届いたものをそのまま使い、NetFlow の機器は snmp 行を 1 行追加します。
ntopngEnterprise 版は SNMP をポーリングして機器のインターフェースをグラフ化します。フローとの比較についてはドキュメントに記載がありません。Community 版の SNMP については記載がありません。
AkvoradoSNMP はフローレコードにインターフェース名と説明を付けるために使い、カウンターは読みません。
ElastiFlow同じく SNMP でインターフェース情報を付与します。比較するには Kibana のグラフを 2 つ自分で作る必要があります。
FastNetMon対象外です。攻撃のしきい値を監視するツールです。
GoFlow2 など対象外です。フローレコードを送り出すことが役割です。

ほかのプロジェクトでは、インターフェースカウンターを読まないか、目で見比べるための別のグラフとして表示するかのどちらかです。数値がずれる理由まで示すプロジェクトは、ほかには見つかりませんでした。

3. 開けばすぐに結論、クエリ言語は不要

概要は、今どれだけのトラフィックがあるか、誰が使っているか、昨日と比べてどうか、に答えます。アドレス、ポート、アプリケーション、国はすべてクリックでき、これだけ表示、除外、フローレコードを見る、詳細ページを開く、といった操作ができます。キーボード入力がほとんど要らないように設計しています。

同じことを、ほかのプロジェクトで行う場合です。

traffic66Web UI とターミナル UI を内蔵し、要約画面から始まります。13 言語に対応し、日本語を含みます。
ntopng情報量の多い完成した UI で、表の中で正面から比較できる唯一のプロジェクトです。公式のお知らせによれば 7 言語に対応しています。
Akvoradoよくできた Web コンソールで、ビジュアライザーでは軸をドラッグしてサンキー図を描けます。使い方はクエリツールに近く、何を調べるかを先に決める必要があります。英語のみです。
ElastiFlowKibana のダッシュボードです。変更するには Kibana を習得する必要があります。
FastNetMonCommunity 版には Web UI がなく、グラフは Grafana を使います。Web UI は商用版にあります。
GoFlow2、pmacct、vflow、nfdumpUI はありません。nfdump はコマンドラインで検索します。ダッシュボードは通常 Grafana で、グラフごとにクエリを書いて作ります。

4. サンプリングされたデータから攻撃を見つける

サンプリングされたデータでの検知は簡単ではありません。1:4096 では、スキャン 1 回分が数パケットしか残らないこともあります。traffic66 のルールは、サンプリング後のデータに合わせて調整しています。デモでは、1:4096 の sFlow を通して、一連の攻撃をすべて検知します。内部スキャン、ポートスキャン、パスワード推測、横展開、新しい宛先への大量アップロード、脅威リストに載ったアドレスとの通信です。デモの通常トラフィック 1 日分では、Web サイトを探るインターネット上のスキャナーを除き、ほかの検知は出ません。

この項目では差が小さくなります。

traffic66スキャン、ポートスキャン、パスワード推測、横展開、通常と異なるアップロード、フラッド、脅威リスト。しきい値はサンプリングされたデータ向けです。
ntopng検知項目は私たちよりはるかに多く、スキャン、フラッド、ブラックリスト、DNS・ICMP によるデータ持ち出し、横展開などが Community 版から使えます。この項目は ntopng が先を行っています。
FastNetMonDDoS に特化していますが、その分深く、数秒以内の検知と BGP ブラックホールの自動起動に対応します。
ElastiFlowNetIntel による脅威情報の付与があり、アラートは Elastic で自分でルールを設定します。
Akvorado とコレクター類セキュリティ検知はありません。

セキュリティについては、ntopng と同水準です。私たちの特長は、検知が設定なしで一つのプログラムに入っていること、そしてサンプリングされたデータ向けに調整されていることです。

もう一つ便利な機能として、traffic66 capture.pcap でパケットキャプチャを同じ画面で分析でき、ライブのデータとは分けて扱われます。ntopng も pcap ファイルを読めるので、この点は互角です。

ほかのプロジェクトが優れている点

選定の前に、この節をお読みください。

Akvorado · GoFlow2

規模

traffic66 は、DuckDB を組み込んだ 1 台のマシンで毎秒 5,000 フローレコードを処理する設計です。通信事業者規模のトラフィックには、スケールアウトできる Kafka と ClickHouse の構成が適しています。

ntopng

ディープパケットインスペクション

ntopng は nDPI により数百種類の L7 プロトコルを識別します。traffic66 はフローを扱うもので、アプリケーションはポート番号で判別し、パケットの中身は解析しません。

FastNetMon

DDoS の自動緩和

FastNetMon は攻撃を検知すると、すぐに BGP ブラックホールや FlowSpec ルールを広報できます。traffic66 はフラッドを報告するだけで、ルーティングには手を加えません。

pmacct

ルーティング情報と柔軟性

pmacct はフローと合わせて BGP・BMP を受け取り、レコードにルーティング情報を付け、ほぼあらゆる出力先に書き込めます。traffic66 は完成品であり、部品を組み合わせるツールキットではありません。

実績のあるプロジェクト

歴史とコミュニティ

ntopng のコミット数は 3 万件近く、nfdump は 20 年にわたって使われてきました。traffic66 はスターを集め始めたばかりで、本番環境での実績ははるかに少ない状態です。

表のほとんどのプロジェクト

ライセンス

これらは OSI 承認のオープンソースライセンスを採用しています。traffic66 はソース公開型で、評価目的と 100 人未満の組織では無償、それより大きな組織は 30 日後に登録が必要です。機能の制限はありませんが、オープンソースではありません。

どれを選ぶか

監視サーバーは 1 台、インターフェースは数十から数百、今日中にグラフを見たい、数値を SNMP（Zabbix など）と合わせたいtraffic66
L7 の可視化が必要、またはミラーポートからの取得が中心ntopng
通信事業者や大規模バックボーンで、毎秒数十万フローAkvorado
DDoS 検知と自動ブラックホールが主目的FastNetMon
Kafka とデータ基盤がすでにあり、コレクターだけが必要GoFlow2 / pmacct
コマンドライン中心で、生のレコードを長期保存したいnfdump

私たちが自信を持って言えるのは三つです。導入が早いこと、読み取りやすいこと、数値が合うこと。それ以外の点については、GitHub の Issue でご意見をお寄せください。差を一つずつ埋めていきます。
