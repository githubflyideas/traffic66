3 مراحل
ڈاؤن لوڈ سے پہلے chart تک

پاکستانی ISPs، جامعات اور اداروں کے لیے یہ کیوں اہم ہے: ڈیٹا آپ کے اپنے server پر

flow records بتاتے ہیں کہ کس نے کس سے، کب اور کتنا رابطہ کیا: اندرونی اور بیرونی addresses، ports اور applications۔ ISPs، جامعات اور سرکاری اداروں میں کوئی tool اپنانے سے پہلے اکثر یہ سوال اٹھتا ہے کہ یہ ڈیٹا کہاں رکھا جائے گا اور اس تک کس کی رسائی ہو گی۔ مارچ 2026 میں اپ ڈیٹ ہونے والی قانونی گائیڈز (DLA Piper اور Chambers) کے مطابق پاکستان میں ابھی ذاتی ڈیٹا کے تحفظ کا کوئی عمومی قانون نافذ نہیں ہوا؛ وزارتِ آئی ٹی و ٹیلی کمیونیکیشن کا تیار کردہ Personal Data Protection Bill 2023 مسودے کی شکل میں ہے اور پارلیمنٹ کے دونوں ایوانوں سے منظور نہیں ہوا۔ DLA Piper کے مطابق اس دوران کچھ پہلوؤں پر Prevention of Electronic Crimes Act 2016 (PECA) لاگو ہوتا ہے۔

یہ قانونی مشورہ نہیں ہے؛ آپ کے معاملے میں flow records ذاتی ڈیٹا شمار ہوتے ہیں یا نہیں، یہ آپ کی قانونی یا compliance ٹیم طے کرے گی۔ تکنیکی طور پر ہم اتنا کہہ سکتے ہیں: collection، storage (embedded DuckDB میں) اور تجزیہ سب ایک ہی مشین پر ہوتا ہے جو آپ کی اپنی ہے، اور پروگرام flow records یا کوئی telemetry باہر نہیں بھیجتا۔ واحد outgoing رابطہ اختیاری ہے: آپ کے کہنے پر DB-IP کے مفت geolocation database کی اپ ڈیٹ۔ اس database کی ایک کاپی پروگرام کے اندر موجود ہے، اس لیے یہ isolated نیٹ ورک میں بھی پوری طرح چلتا ہے۔ اور چونکہ نہ Kafka cluster چاہیے نہ Elasticsearch، اس لیے پہلے سے موجود ایک Windows یا Linux PC کافی ہے؛ 100 سے کم افراد والے اداروں کے لیے یہ مفت ہے۔

اگر آپ کے نیٹ ورک میں MikroTik router ہیں: MikroTik کی documentation کے مطابق RouterOS کا Traffic Flow فیچر NetFlow v1، v5، v9 اور IPFIX بھیجتا ہے، اور RouterOS v7 میں packet sampling بھی موجود ہے۔ traffic66 انہیں براہِ راست وصول کرتا ہے؛ RouterOS 7 کی setup دو lines کی ہے اور README میں دی گئی ہے۔ جو device اپنا sampling rate نہیں بتاتا، اس کا rate inventory.txt میں ایک line سے لکھا جا سکتا ہے، تاکہ اعداد درست رہیں۔

2. کیا اعداد interface counters سے میل کھاتے ہیں؟

یہ سوال ہر flow tool سے پوچھا جاتا ہے: chart کہتا ہے uplink پر 800 Mb/s ہیں، Zabbix میں SNMP کہتا ہے 600۔ صحیح کون ہے؟

flow کے اعداد اندازے ہوتے ہیں: sample کیے گئے packets ضرب sampling rate۔ traffic66 میں اسی کام کے لیے ایک صفحہ ہے، انٹرفیس جانچ۔ یہ ہر interface کا flow سے نکلا اندازہ اور device کے اپنے counters (sFlow counters یا SNMP) ایک ہی chart میں دکھاتا ہے، اور فرق اور sampling کی statistical error کا حساب لگاتا ہے۔ جب فرق اس سے زیادہ ہو جتنا sampling سے سمجھ آتا ہے، تو یہ ممکنہ وجہ بتاتا ہے: کچھ interfaces sample نہیں ہو رہے، ایک ہی ٹریفک دو interfaces پر sample ہو رہی ہے، export packets راستے میں گم ہو رہے ہیں، یا sampling rate ابھی موصول نہیں ہوا۔

اس کے پیچھے کچھ خاموش تفصیلات ہیں: وہ sampling rate جو device نے واقعی لاگو کیا؛ records کو اس وقت تک روکے رکھنا جب تک ان کا sampling rate نہ آ جائے، بجائے انہیں 1:1 گننے کے؛ گم ہونے والے export packets کی تلافی؛ لمبے flows کو ان منٹوں پر پھیلانا جتنی دیر وہ چلے؛ اور NetFlow کے byte counts میں Ethernet overhead شامل کرنا، کیونکہ interface counters میں یہ شامل ہوتا ہے۔

دوسرے کہاں تک جاتے ہیں:

traffic66flow کا اندازہ اور device counters ایک chart میں، فرق اور statistical error کا حساب، اور وجہ واضح۔ sFlow counters جیسے آتے ہیں ویسے استعمال ہوتے ہیں؛ NetFlow device کے لیے ایک snmp line۔
ntopngEnterprise edition SNMP poll کرتا ہے اور device interfaces کے charts بناتا ہے؛ documentation میں انہیں flows سے ملانے کا ذکر نہیں۔ Community edition میں SNMP documented نہیں۔
AkvoradoSNMP کو flow records پر interface کے نام اور descriptions کے لیے استعمال کرتا ہے، counters کے لیے نہیں۔
ElastiFlowیہ بھی SNMP کو interface کی تفصیلات کے لیے استعمال کرتا ہے؛ موازنے کے لیے Kibana کے دو charts خود بنانے پڑتے ہیں۔
FastNetMonیہ اس کا کام نہیں؛ یہ حملوں کی thresholds پر نظر رکھتا ہے۔
GoFlow2 اور دیگریہ ان کا کام نہیں؛ یہ flow records فراہم کرتے ہیں۔

باقی جگہوں پر interface counters یا تو پڑھے ہی نہیں جاتے، یا ایک اور chart کی صورت میں دکھائے جاتے ہیں جسے آنکھ سے ملانا پڑتا ہے۔ ہمیں کوئی اور project نہیں ملا جو بتائے کہ اعداد میں فرق کیوں ہے۔

3. کھولتے ہی نتیجہ، کوئی query language نہیں

جائزہ بتاتا ہے کہ اس وقت کتنی ٹریفک ہے، کون استعمال کر رہا ہے، اور کل کے مقابلے میں کیا صورت ہے۔ ہر address، port، application اور ملک پر کلک کیا جا سکتا ہے: صرف یہی دکھائیں، اسے نکال دیں، اس کے flow records کھولیں، اس کا تفصیلی صفحہ کھولیں۔ interface اس طرح بنایا گیا ہے کہ ٹائپ کرنے کی ضرورت کم ہی پڑے۔

4. sampled ڈیٹا میں حملے ڈھونڈنا

sampled ڈیٹا پر detection مشکل ہے: 1:4096 پر ایک scan کے صرف چند packets ہاتھ آتے ہیں۔ traffic66 کے rules sampled ڈیٹا کے لیے calibrate کیے گئے ہیں۔ demo میں حملے کا پورا سلسلہ 1:4096 sFlow کے ذریعے پکڑا جاتا ہے: اندرونی scan، port scan، پاس ورڈ کا اندازہ (password guessing)، lateral movement، ایک نئے address پر بڑا upload، اور threat list والی ٹریفک۔ demo کی ایک دن کی عام ٹریفک سے کوئی اور نتیجہ نہیں نکلتا، سوائے اس internet scanner کے جو website کا دروازہ کھٹکھٹاتا ہے۔

لائسنس

کون سا چنیں

ایک مشین (پہلے سے موجود PC بھی)، دسیوں سے سینکڑوں interfaces، آج ہی charts، اور SNMP سے میل کھاتے اعدادtraffic66
Layer-7 کی visibility، یا زیادہ تر mirror portsntopng
بڑا carrier یا backbone، لاکھوں flows فی سیکنڈAkvorado
خودکار blackholing کے ساتھ DDoS detectionFastNetMon
Kafka اور data platform پہلے سے چل رہے ہیں اور صرف collector چاہیےGoFlow2 / pmacct
Command line، طویل مدت کے لیے raw recordsnfdump

ہمیں تین باتوں پر اعتماد ہے: جلدی انسٹال، آسانی سے سمجھ آنے والا، اور میل کھاتے اعداد۔ باقی کے لیے GitHub پر issues کا خیر مقدم ہے؛ ہم کمیاں ایک ایک کر کے دور کریں گے۔
