अगर आपके network के edge पर MikroTik router है, तो शुरुआत आसान है। MikroTik के official documentation के अनुसार RouterOS का Traffic Flow feature NetFlow v1, v5, v9 और IPFIX export करता है। traffic66 NetFlow v5/v9 और IPFIX किसी भी UDP port पर लेता है, इसलिए router पर /ip traffic-flow set enabled=yes और collector के address के साथ /ip traffic-flow target add, इन दो lines से data आने लगता है। NetFlow में interface counters नहीं आते; इंटरफ़ेस मिलान के लिए traffic66 में एक snmp line जोड़ें और RouterOS पर SNMP चालू करें, जो default में बंद रहता है और जिसकी MIBs में IF-MIB शामिल है।

किसी college, छोटी company या local operator के पास अक्सर अलग server का बजट नहीं होता, पर एक Windows PC या Linux machine पहले से मौजूद होती है। traffic66 evaluation के लिए और 100 से कम लोगों वाली organizations के लिए मुफ़्त है, और उसी machine पर बिना किसी अतिरिक्त service के चलता है।

Flow records में users के IP addresses होते हैं। traffic66 इन्हें आपकी अपनी machine पर, embedded DuckDB में रखता है; इन्हें किसी cloud service पर भेजने की ज़रूरत नहीं पड़ती। भारत में डिजिटल personal data के लिए Digital Personal Data Protection Act, 2023 बनाया गया है। आपके flow data पर यह क़ानून कैसे लागू होता है, यह अपने legal सलाहकार से पूछें; यह लेख क़ानूनी सलाह नहीं है। हम सिर्फ़ इतना कहते हैं कि data कहाँ रखा है, यह फ़ैसला आपके हाथ में रहता है।

2. क्या आँकड़े interface counters से मेल खाते हैं?

हर flow tool से यही सवाल पूछा जाता है: chart कहता है uplink पर 800 Mb/s है, Zabbix में SNMP 600 बताता है। सही कौन है?

Flow के आँकड़े अनुमान होते हैं: sample किए गए packets गुणा sampling rate। traffic66 में ठीक इसी काम के लिए एक page है, इंटरफ़ेस मिलान। यह हर interface का flow अनुमान और device के अपने counters (sFlow counters या SNMP) एक ही chart में दिखाता है, और दोनों का अंतर तथा sampling की statistical error निकालता है। जब अंतर sampling से समझ में आने वाली सीमा से ज़्यादा हो, तो यह संभावित कारण बताता है: कुछ interfaces पर sampling नहीं है, एक ही traffic दो interfaces पर sample हो रहा है, export packets रास्ते में खो गए, या sampling rate अभी तक मिला ही नहीं।

इसके पीछे कुछ बारीक बातें हैं: device ने असल में जो sampling rate लगाया, वही इस्तेमाल होता है; sampling rate आने तक records रोककर रखे जाते हैं, उन्हें 1:1 नहीं गिना जाता; खोए हुए export packets की भरपाई की जाती है; लंबे flows को उन मिनटों में बाँटा जाता है जितनी देर वे चले; और NetFlow byte counts में Ethernet overhead जोड़ा जाता है, क्योंकि interface counters में वह शामिल होता है।

दूसरे projects इसमें कहाँ तक जाते हैं:

traffic66Flow अनुमान और device counters एक chart में, अंतर और statistical error की गणना, कारण साफ़ लिखा हुआ। sFlow counters आते ही इस्तेमाल होते हैं; NetFlow device के लिए एक snmp line।
ntopngEnterprise edition SNMP poll करता है और device interfaces के charts बनाता है; documentation में इन्हें flows से मिलाने की बात नहीं है। Community edition में SNMP documented नहीं है।
AkvoradoSNMP का इस्तेमाल flow records पर interface के नाम और description के लिए करता है, counters के लिए नहीं।
ElastiFlowयह भी interface की जानकारी जोड़ने के लिए SNMP लेता है; तुलना के लिए दो Kibana charts ख़ुद बनाने पड़ते हैं।
FastNetMonयह इसका काम नहीं; यह attack thresholds पर नज़र रखता है।

बाक़ी जगह interface counters या तो पढ़े ही नहीं जाते, या एक और chart की तरह दिखते हैं जिसे आँख से मिलाना पड़ता है। ऐसा कोई दूसरा project हमें नहीं मिला जो बताए कि आँकड़े अलग क्यों हैं।

4. Sampled data में attacks ढूँढना

Sampled data पर detection कठिन है: 1:4096 पर किसी scan के बस गिने-चुने packets बचते हैं। traffic66 के rules sampled data के हिसाब से calibrate किए गए हैं। Demo में पूरी attack chain 1:4096 sFlow से पकड़ी जाती है: internal scan, port scan, password guessing, lateral movement, किसी नए address पर बड़ा upload, और threat list traffic। Demo के एक दिन के सामान्य traffic से कोई दूसरी finding नहीं निकलती, सिवाय उस internet scanner के जो website का दरवाज़ा खटखटाता है।

यहाँ मुक़ाबला ज़्यादा क़रीबी है:

traffic66Scans, port scans, password guessing, lateral movement, असामान्य uploads, floods और threat lists, sampled data के लिए thresholds के साथ।
ntopngहमसे कहीं ज़्यादा checks: scans, floods, blacklists, DNS और ICMP exfiltration, lateral movement, और ये Community edition में ही। यहाँ ntopng आगे है।
FastNetMonसिर्फ़ DDoS, पर गहराई से: कुछ ही सेकंड में detection और अपने-आप BGP blackholing।
ElastiFlowNetIntel threat enrichment; alerting उन rules से जो आप Elastic में बनाते हैं।
Akvorado और collectorsकोई security detection नहीं।

Security में हम ntopng के बराबर हैं। हमारी ख़ासियत यह है कि ये checks एक ही program में, बिना setup के आते हैं और sampled data के लिए tune किए गए हैं।

एक और सुविधा: traffic66 capture.pcap किसी packet capture का विश्लेषण उन्हीं pages से करता है, live data से अलग रखकर। ntopng भी pcap files पढ़ता है, इसलिए इसे बराबरी मानिए।
